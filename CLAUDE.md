# CLAUDE.md — Vallavan OTT Platform

Operating guide for any AI/dev agent working in this repo. Read this first, then `PROJECT_STATE.md` for where things stand today.

## What this is

**Vallavan** — a Tamil-first documentary OTT + advertising platform. Free ad-supported viewing (AVOD), sponsor-funded, with a wallet-based pay-per-published-post ad model and Tamil Nadu district-level geo-targeting.

- **Frontend** (this repo root): Vite + React 18 + TypeScript + Tailwind SPA, generated by Bolt. Already built. Serves viewers, sponsors (Business Center), and admins (CMS).
- **Backend** (`backend/`): NestJS + Prisma service layer for sensitive/business logic (wallet, campaign approval, admin mutations, social publishing).
- **Data + Auth + Storage**: Supabase (Postgres + Auth + Storage). Frontend reads content directly via `@supabase/supabase-js`; writes and money-touching logic go through the NestJS API.
- **Payments**: Razorpay (wallet top-ups only).
- **Social publishing**: Meta Graph API (Facebook Page + Instagram Business).
- **SEO/AEO/GEO** (`seo-site/`, Phase 5): a separate SSR public site (Next.js) for crawlable pages — the SPA itself stays CSR.

## The one hard rule: DO NOT TOUCH FRONTEND UI CODE

This is an **integration-only** task on the frontend. The Bolt-generated UI/UX, navigation, styling, and component structure must stay **exactly as built**.

**The only permitted change to existing files under `src/components/`, `src/screens/`, `src/context/`, `src/hooks/`:** swapping static imports from `src/data/mockData.ts` for real data fetched from the backend — **preserving the exact TypeScript interfaces already in `mockData.ts`**, so zero UI code changes.

- You MAY add new files: `src/lib/supabase.ts`, `src/services/*.ts`, `src/hooks/useDocumentaries.ts`, etc.
- You MAY build a new `SplashScreen` animation (explicitly requested) — it is net-new polish, not a data swap, and must still transition into Home exactly as `App.tsx` expects (`onDone` callback).
- You MAY edit `index.html`, `manifest.json`, `vite.config.ts`, `package.json`, and add a service worker — PWA/build config is not UI.
- You may NOT change JSX structure, class names, props, layout, or component logic anywhere else.

If a data-shape mismatch tempts you to change a component: **don't**. Shape the data in the service/hook layer to match the interface instead. See `CURRENT_SPEC.md` §"Locked constraint".

## Hard boundaries (require explicit human approval — never do autonomously)

1. **No deploy** to any VM/server.
2. **No live Razorpay transaction.**
3. **No publish** to Meta/Facebook/Instagram APIs.
4. **No push to `main`/`master`** — only the working branch `backend-integration-dev`.

Everything else in local development proceeds autonomously; log non-trivial choices in `PROJECT_STATE.md`.

## Data flow contract

`mockData.ts` defines the canonical shapes: `Documentary`, `InspireItem`, `LiveSlot`, `AdContent`, `FeedReel`, `Genre`, plus arrays (`campaigns`, `adminUsers`, `tamilNaduDistricts`, etc.). The database schema is derived **field-for-field** from these (see `supabase/schema.sql` / `backend/prisma/schema.prisma`). Services return objects that satisfy these interfaces exactly — including display-formatted strings like `duration: "24:18"` and `uploaded: "Aug 10, 2024"` (formatted in the service layer from real timestamps).

## Git workflow

- Branch: `backend-integration-dev` (never `main`).
- Remote: `git@github.com-vallavan:vallavanmagazine/ott.git` (the `-vallavan` host alias is required — this machine multiplexes SSH keys by host alias; plain `github.com` will not authenticate correctly).
